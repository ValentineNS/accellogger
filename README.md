# Акселерометр (AccelLogger) — iPhone SE (2016)

iOS-приложение, которое снимает показания встроенного акселерометра и считает:

1. **Ускорение** по осям (X, Y, Z) и «главное» ускорение (модуль).
2. **Скорость** по осям и главную скорость.
3. **Перемещение** по осям и главное перемещение (расстояние от начальной точки).

Все величины — как функции времени. По нажатию кнопки данные собираются в
**книгу Excel** (.xlsx): таблица всех отсчётов + 12 графиков — и отправляются
на e-mail вложением.

---

## 1. Как это работает

- Данные берутся из `CoreMotion` (`CMMotionManager`, режим `deviceMotion`).
- Используется `userAcceleration` — ускорение **без учёта гравитации**
  (CoreMotion сам вычитает вектор гравитации по гироскопу). Это важно: если
  интегрировать «сырое» ускорение акселерометра вместе с g≈9.8 м/с², скорость и
  перемещение будут расти с огромной ошибкой.
- Значение `userAcceleration` у CoreMotion задано **в единицах g**; для перевода
  в м/с² умножаем на `9.80665`.
- Опционально ускорение пересчитывается в **неподвижную (мировую) систему
  координат** через матрицу поворота `attitude.rotationMatrix`. Тогда оси не
  «вращаются» вместе с телефоном — что правильно для оценки перемещения.
- Интегрирование — метод трапеций:
  `v += (a + a_пред) / 2 · dt`, `s += v · dt`.

### Статистическая обработка сигнала

Обработка выполняется **после остановки записи** — по всему массиву отсчётов
сразу (это позволяет применять некаузальные фильтры, у которых нет задержки):

1. **Подавление выпадающих точек** — фильтр Хампеля. В скользящем окне
   считается медиана и медианное абсолютное отклонение (MAD); отсчёт, который
   отклонился больше чем на заданное число σ, заменяется медианой окна.
2. **Медианный фильтр** (окно 3) — убирает одиночные импульсы.
3. **Адаптивное сглаживание** — скользящее среднее, окно подбирается
   автоматически: оно растёт, пока невязка «данные − сглаженное» остаётся на
   уровне шума. Шум снимается максимально, но реальный сигнал не «съедается».
4. **Фильтр Калмана** — состояние `[перемещение, скорость, ускорение]` на каждую
   ось; ускорение наблюдается, скорость и перемещение получаются интегрированием
   с коррекцией. Фильтр сам оценивает неопределённость (доверительный интервал
   перемещения). При обнаружении покоя выполняется обнуление скорости (ZUPT) —
   это резко снижает дрейф.
5. **Статистика** — среднее, СКО, минимум/максимум, СКЗ, асимметрия, эксцесс,
   уровень шума и число отброшенных выбросов по каждой оси.

Обработанные данные попадают в таблицу и на графики; рядом сохраняются и
**сырые** отсчёты датчика.

### Про дрейф (важно понимать)

Скорость и перемещение напрямую из акселерометра точно получить нельзя: это
двойное интегрирование, и любая малая погрешность ускорения и смещение нуля
накапливаются. Практика:

- для коротких движений (секунды) результат вполне осмысленный;
- на длинных интервалах перемещение «уползает».

Статистическая обработка (подавление выбросов, сглаживание, фильтр Калмана с
обнулением скорости в покое) заметно ограничивает рост ошибки, но полностью его
не устраняет. Для реального определения перемещения на длинных дистанциях нужны
другие средства: GPS, ARKit, или сенсорное слияние — их в этом приложении нет.

## 2. Требования

- **iPhone SE (2016)** поддерживается: он умеет `deviceMotion` (акселерометр +
  гироскоп). Максимальная версия iOS для него — **iOS 15.8.x**, приложение
  рассчитано на iOS 15.
- Собрать приложение можно **только на macOS с Xcode** (Windows/iOS-эмулятора для
  сборки iOS-приложений не существует). Xcode 13+ (лучше 14/15).
- Для установки на реальный телефон — бесплатный Apple ID (личная подпись) или
  платный аккаунт разработчика.

## 4. Сборка — вариант A (ручной, самый простой)

1. На Mac откройте **Xcode → File → New → Project → iOS → App**.
2. Назовите проект `AccelLogger`, Interface — **SwiftUI**, Language — **Swift**.
3. Удалите автоматически созданные `AccelLoggerApp.swift` и `ContentView.swift`
   (правый клик → Delete → Move to Trash).
4. Перетащите в проект все файлы из папки `AccelLogger/AccelLogger/`
   (кроме `Info.plist`).
5. Откройте настройки проекта → вкладка **Info** и добавьте строку:
   - Key: `Privacy - Motion Usage Description`
   - Value: `Доступ к акселерометру нужен для измерения ускорения, скорости и перемещения.`
6. Выберите целевое устройство (ваш iPhone SE), подключите телефон, нажмите ▶.

## 4.1. Сборка — вариант B (через XcodeGen)

Если установлен [XcodeGen](https://github.com/yonaskolb/XcodeGen) (`brew install xcodegen`):

```bash
cd AccelLogger
xcodegen generate
open AccelLogger.xcodeproj
```

Затем выберите свою команду подписи (Signing & Capabilities → Team) и запустите на
телефоне.

## 5. Как пользоваться

1. Запустите приложение и разрешите доступ к движению (если спросит).
2. При необходимости настройте частоту опроса (по умолчанию 50 Гц), мировую
   систему координат и параметры статистической обработки (раздел
   «Статистическая обработка»).
3. Нажмите **«Начать запись»** и выполните движение. В разделе «Текущие значения»
   в реальном времени видно ускорение; раздел **«Графики»** (ссылка в главном
   меню) показывает кривую. Скорость и перемещение считаются **после остановки**.
4. Нажмите **«Остановить»** — запустится статистическая обработка всего массива
   отсчётов (индикатор «Обработка…»), после чего появятся итоги сеанса.
   Кнопка **«Обработать заново»** позволяет пересчитать данные с другими
   параметрами без повторной записи.
5. Введите адрес получателя (необязательно) и нажмите **«Отправить Excel
   на e-mail»** — откроется окно письма с уже вложенной книгой Excel; останется
   нажать «Отправить».
6. Если почта на устройстве не настроена — кнопка **«Поделиться Excel-файлом»**
   позволит отправить файл любым приложением (в т.ч. через почту, мессенджер,
   файлы iCloud). Там же доступен и **«Поделиться CSV-файлом»** (простая таблица
   без графиков).

## 6. Формат файла

Имя: `motion_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.csv`.
Разделитель колонок — `;`, десятичный разделитель — `.` (открывается в Excel,
Numbers, любой текстовый редактор).

| Колонка          | Что это                                  | Единица |
|------------------|------------------------------------------|---------|
| `N`              | номер отсчёта                            | —       |
| `t, s`           | время от начала записи                   | с       |
| `ax, м/с2` …     | ускорение по осям X, Y, Z                | м/с²    |
| `a, м/с2`        | главное ускорение (модуль)               | м/с²    |
| `Vx, м/с` …      | скорость по осям                         | м/с     |
| `V, м/с`         | главная скорость (модуль)                | м/с     |
| `Sx, м` …        | перемещение по осям                      | м       |
| `S, м`           | главное перемещение (расстояние от старта)| м      |
| `ax_raw, м/с2` … | **сырое** ускорение датчика (до обработки)| м/с²   |

Обработанные величины (`ax…S`) — результат статистического тракта; `ax_raw`,
`ay_raw`, `az_raw` — необработанное ускорение в системе координат устройства,
как его отдаёт датчик (без компенсации смещения нуля).

Пример начала файла:

```
N;t, s;ax, м/с2;ay, м/с2;az, м/с2;a, м/с2;Vx, м/с;Vy, м/с;Vz, м/с;V, м/с;Sx, м;Sy, м;Sz, м;S, м;ax_raw, м/с2;ay_raw, м/с2;az_raw, м/с2
0;0.000000;0.019613;-0.009804;0.009804;0.023917;0.000000;0.000000;0.000000;0.000000;0.000000;0.000000;0.000000;0.000000;0.019613;-0.009804;0.009804
1;0.020000;0.029420;0.000000;0.019613;0.035359;0.000490;0.000000;0.000098;0.000500;0.000005;0.000000;0.000001;0.000005;0.029420;0.000000;0.019613
```

## 6.1. Книга Excel (.xlsx)

Основной формат выгрузки — **книга Excel**, имя `motion_ГГГГ-ММ-ДД_ЧЧ-ММ-СС.xlsx`.
Файл создаётся самим приложением без внешних библиотек (`.xlsx` — это ZIP-архив
с XML-частями, архивация без сжатия — полностью поддерживается Excel).

Книга состоит из 16 листов:

- **«Данные»** — таблица всех обработанных отсчётов (заголовки с нижними/верхними
  индексами: x/y/z — подстрочные, «2» в м/с² — надстрочный);
- **12 листов-диаграмм** — по одному графику «величина → время» на листе:
  - «Ускорение X/Y/Z» и «Главное ускорение»;
  - «Скорость X/Y/Z» и «Главная скорость»;
  - «Перемещение X/Y/Z» и «Главное перемещение»;
- **«Сырые данные»** — необработанное ускорение датчика (`ax_raw`, `ay_raw`,
  `az_raw`) со временем;
- **«Статистика»** — характеристики сеанса: длительность, фактическая частота,
  число отброшенных выбросов, а по каждой оси — среднее, СКО, минимум, максимум,
  СКЗ, асимметрия, эксцесс, уровень шума;
- **«ГрафикДанные»** — служебный скрытый лист с прореженными данными, на которые
  ссылаются диаграммы.

Чтобы Excel не тормозил на очень длинных записях, в диаграммы попадает до 300
равномерно выбранных точек (лист «Данные» при этом содержит **все** отсчёты).
Диаграммы нативные: их можно увеличивать, наводить курсор, копировать и
редактировать.

## 7. Про автоматическую отправку письма без участия пользователя

`MFMailComposeViewController` из Apple **всегда** показывает окно письма — так
устроена платформа (приложения не могут молча отправлять письма через почтовый
ящик пользователя). Возможные варианты автоматизации:

- **Вручную** (как сейчас) — пользователь нажимает «Отправить». Надёжно и не
  требует интернета/сервера.
- **Через собственный сервер/сервис** (например, SendGrid, Mailgun, SMTP) —
  приложение отправляет CSV по HTTPS на сервер, а сервер шлёт письмо. Для этого
  нужен API-ключ и доступ к сети; при желании легко добавить экран настроек
  сервера и отправку через `URLSession`.
- **Экспорт в iCloud Drive / «Файлы»** и синхронизация — если письмо не
  обязательно.

## 8. Замечания по точности и настройке

- Реальная частота может отличаться от заданной (Core Motion ограничивает
  диапазон и «нормализует» значение). В файле указано **фактическое** время
  каждого отсчёта, поэтому расчёты корректны независимо от частоты.
- `time_s` берётся из системных меток `motion.timestamp` — это монотонное время,
  устойчивое к смене часов.
- Ось Z у лежащего экраном вверх телефона направлена вверх; оси устройства —
  X вправо, Y вверх, Z от экрана (стандарт CoreMotion).
- Для экспериментов со степенью сглаживания Калмана попробуйте значения 0,3–0,7.

## 9. Установка без Mac: Windows + GitHub + Sideloadly

Этот путь полностью работает с Windows. Сборка идёт в облаке GitHub
(бесплатные минуты для публичных и приватных репозиториев), а установка на iPhone —
через Sideloadly.

### Шаг 1. Подготовить папку как репозиторий

В папке `AccelLogger` (там, где лежат `project.yml`, `README.md` и `.github`)
выполните:

```bash
git init
git add .
git commit -m "AccelLogger"
```

### Шаг 2. Загрузить на GitHub

1. Зарегистрируйтесь на github.com.
2. Создайте новый **пустой** репозиторий, например `accellogger` (без README).
3. Выполните (замените `ВАШ_ЛОГИН`):

```bash
git remote add origin https://github.com/ВАШ_ЛОГИН/accellogger.git
git branch -M main
git push -u origin main
```

### Шаг 3. Дождаться сборки

- Откройте вкладку **Actions** в репозитории. Workflow `Build unsigned IPA`
  запустится сам после push.
- Через несколько минут откройте завершённый запуск → внизу в разделе
  **Artifacts** скачайте **`AccelLogger-ipa`** (это zip, внутри `AccelLogger.ipa`).
- Если сборка упала — напишите мне, посмотрим лог.

### Шаг 4. Установить на iPhone (Sideloadly, Windows)

1. Скачайте **Sideloadly** (sideloadly.io) и **iTunes** с сайта Apple (не из
   Microsoft Store, а классический установщик — для драйверов устройства).
2. Подключите iPhone SE кабелем, ответьте на телефоне «Доверять этому компьютеру».
3. Откройте Sideloadly:
   - **IPA**: выберите `AccelLogger.ipa`;
   - **Apple ID**: введите свой бесплатный Apple ID;
   - нажмите **Start**, введите пароль Apple ID (если включена двухфакторная
     аутентификация — используйте пароль приложения, либо Sideloadly попросит
     подтвердить вход).
4. Если Sideloadly предложит сменить Bundle ID на личный — согласитесь
   (например, `com.ВАШЛОГИН.accellogger`).
5. После установки на iPhone: *Настройки → Основные → VPN и управление
   устройством → Профиль разработчика → Доверять*.
6. Запускайте приложение.

> iPhone SE (2016) работает максимум на iOS 15, а требование «Режим разработчика»
> появилось только в iOS 16 — поэтому включать его не нужно, установка проще.

### Шаг 5. Продление подписи

Бесплатный Apple ID подписывает приложение **на 7 дней**. По истечении срока
приложение перестанет запускаться. Просто повторите Шаг 4 (Sideloadly умеет
хранить настройки и обновлять подпись одной кнопкой). Данные при этом сохраняются,
само приложение не удаляется.

Более удобно — приложение **AltStore** (altstore.io), которое обновляет подписи
автоматически по Wi-Fi.

### Альтернатива без Sideloadly

Mac в облаке (MacinCloud, MacStadium): берёте доступ, подключаетесь по VNC,
ставите Xcode и делаете всё как в разделе 4, включая кнопку Run на реальном
устройстве.

## 10. Калибровка смещения нуля

Реальный акселерометр в покое показывает не ровно 0, а небольшой сдвиг —
**смещение нуля** (обычно 0,1–0,3 м/с², т.е. 1–3 % от g). Это нормально, но при
интегрировании постоянное смещение даёт растущую ошибку скорости и перемещения.

Приложение умеет измерять и **вычитать** это смещение двумя способами:

- **Автокалибровка при старте** (включена по умолчанию) — после нажатия «Начать
  запись» телефон нужно подержать неподвижно ~1,5 с. За это время измеряется
  среднее смещение, и оно вычитается из всех последующих замеров. В строке
  состояния видно прогресс «Калибровка… N %».
- **Кнопка «Калибровка (обнуление)»** — можно откалибровать в любой момент
  (в том числе до записи), положив телефон неподвижно.

Текущее измеренное смещение по осям отображается в разделе «Состояние» строкой
**«Смещение нуля»**. После калибровки значения ускорения в покое становятся
близки к нулю.

Примечание: смещение зависит от температуры и осей, поэтому со временем его стоит
повторять. Абсолютно точное перемещение из одного акселерометра получить всё равно
нельзя — для длинных дистанций нужны GPS или ARKit.

## 11. Графики

В главном меню есть раздел **«Графики»**. На отдельном экране можно посмотреть
изменение величин во времени:

- выберите **величину**: Ускорение / Скорость / Перемещение;
- выберите **ось**: X / Y / Z / Модуль;
- график ускорения обновляется прямо во время записи, а скорость и перемещение
  появляются после статистической обработки (после остановки);
- под графиком показаны **текущее, минимальное и максимальное** значения.

Если выбрана конкретная ось, дополнительно тонкой серой линией показан **модуль**
(результирующая по трём осям).

> На iPhone SE доступна максимум iOS 15, а системный фреймворк графиков
> (Swift Charts) требует iOS 16. Поэтому график нарисован самостоятельно через
> `Canvas` — он корректно работает на iOS 15.

При большом числе отсчётов (например, несколько минут при 50 Гц) для отрисовки
точки автоматически **прореживаются** до ~400 — это заметно ускоряет экран, не
влияя на точность данных в файле.

## 12. Подавление выпадающих точек (фильтр Хампеля)

Реальный датчик иногда выдаёт **выпадающие точки** — одиночные резкие всплески,
сильно оторванные от соседних отсчётов. При интегрировании такой всплеск даёт
большую ошибку скорости и перемещения, поэтому его нужно убрать.

В разделе **«Статистическая обработка»** есть ползунок **«Порог выбросов
(Хампель)»** (0 … 6 σ):

- для каждого отсчёта берётся окно соседних значений, считается медиана и
  медианное абсолютное отклонение (MAD);
- если отсчёт отклонился от медианы больше чем на порог·σ (σ = 1,4826·MAD), он
  заменяется медианой окна;
- `0` — фильтр выключен.

По умолчанию **3 σ** — стандартный порог: отбрасываются только явные выбросы.
Метод робастный: в отличие от среднего, медиана не «тянется» к выбросу, поэтому
фильтр не искажает нормальные данные. Число отброшенных выбросов видно в
разделе **«Итоги сеанса»** и на листе «Статистика» книги Excel.

## 13. Адаптивное сглаживание и медианный фильтр

Реальный акселерометр всегда даёт **шум**: показания колеблются вокруг средней
кривой даже при плавном движении. На графике это выглядит как «пила»/рябь.

В разделе **«Статистическая обработка»** есть ползунок **«Адаптивное
сглаживание»** (0 … 0,5 с):

- значение — это **максимальная ширина окна** скользящего среднего;
- перед сглаживанием проходит медианный фильтр (окно 3) — он убирает одиночные
  импульсы;
- окно подбирается **автоматически**: оно растёт, пока невязка «данные −
  сглаженное» остаётся на уровне шума. Так снимается максимум шума, но реальный
  сигнал не «съедается»;
- `0` — сглаживание выключено (кроме медианного фильтра).

По умолчанию задано **0,20 с**. Сглаживание применяется к ускорению **до
интегрирования**, поэтому оно заодно уменьшает дрейф. Данные в файлах и на
графике согласованы между собой.

Совет по подбору: для ходьбы/тряски 0,05–0,15 с; чтобы подчеркнуть плавные
движения — 0,25–0,40 с.

## 14. Фильтр Калмана

Фильтр Калмана — основной элемент «серьёзной» обработки. Для каждой оси он ведёт
состояние **`[перемещение, скорость, ускорение]`**: ускорение наблюдается
напрямую, а скорость и перемещение получаются интегрированием с коррекцией.

В разделе **«Статистическая обработка»**:

- переключатель **«Фильтр Калмана»** — включает/выключает его;
- ползунок **«Степень сглаживания»** (0 … 1) — чем больше, тем глаже оценки
  (сильнее ограничивается «рывок» — скорость изменения ускорения).

Даёт два эффекта: сглаживает ускорение (фильтр сам оценивает уровень шума) и
**снижает дрейф** скорости и перемещения. Дополнительно фильтр оценивает
неопределённость — в «Итогах сеанса» показывается доверительный интервал
перемещения (неопределённость итоговой точки, м).

Если фильтр выключен, скорость и перемещение считаются прямым интегрированием
методом трапеций (см. раздел 1).

Совет по подбору: начните с **0,5**; больше сглаживания — при шумном датчике,
меньше — если нужно точнее передать резкие удары.

## 15. Порог чувствительности и порог скорости

Даже после сглаживания в покое остаётся мелкое «дрожание» нуля. Два порога
чистят данные:

- **«Порог чувствительности»** (0 … 1,0 м/с²) — ускорение слабее порога
  считается шумом покоя и обнуляется. По умолчанию **0,05 м/с²** (≈ 0,005 g).
- **«Порог скорости»** (0 … 0,5 м/с) — скорость слабее порога обнуляется, чтобы
  перемещение не «уползало» после остановки. По умолчанию **0,05 м/с** (5 см/с).

Оба порога применяются в статистическом тракте (при постобработке). `0` —
порог выключен.

Совет по подбору: если телефон лежит неподвижно, а линия дрожит — увеличьте
порог чувствительности (обычно 0,05–0,15 м/с²); если после остановки
перемещение продолжает расти — увеличьте порог скорости (обычно 0,02–0,10 м/с).
Слишком большие пороги начнут «съедать» слабые движения.

## 16. Подавление дрейфа (обнуление скорости в покое)

Дополнительно к фильтру Калмана можно включить **«Подавлять дрейф (обнуление в
покое)»**. При обнаружении состояния покоя (ускорение ниже порога в течение
~0,3 с) в фильтр Калмана подаётся псевдоизмерение нулевой скорости — скорость
принудительно обнуляется (метод ZUPT, zero-velocity update). Это резко снижает
накопление перемещения после остановки. Включено по умолчанию.
